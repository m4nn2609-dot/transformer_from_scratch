# Transformer from Scratch

A hand-written decoder-only language model built from scratch following the
Stanford CS336 (Language Modeling from Scratch) approach. Every core component
is implemented from raw PyTorch operations — no `nn.MultiheadAttention`, no
Hugging Face tokenizers — with tests comparing each component against its PyTorch
reference via `torch.allclose`.

## Target Configuration

| Hyperparameter | Value |
|----------------|-------|
| Parameters | ~22M |
| d_model | 512 |
| n_layers | 4 |
| n_heads | 16 |
| d_ff | 2048 |
| Vocab size | 10,000 |
| Weight tying | Input embedding ↔ output projection |
| Positional encoding | RoPE (Rotary Positional Embeddings) |
| Normalization | RMSNorm |
| Activation | SwiGLU |
| Dataset | TinyStories (~51 MB slice) |

## Phase 1 — Byte-Level BPE Tokenizer

Train the optimized BPE tokenizer and encode the dataset to a uint16 memmap:

```bash
python tokenizer/encode_dataset.py
```

This produces:
- `data/tokenizer/vocab.txt` — id ↔ hex bytes mapping (10,000 entries)
- `data/tokenizer/merges.txt` — ordered merge rules (9,743 merges)
- `data/tokenizer/tinystories_uint16.bin` — tokenized dataset (12.5M tokens, 23.92 MB)

### Optimizations
- **Multiprocessing pre-tokenization**: file split at `<|endoftext|>` boundaries, chunks counted in parallel workers, Counters merged in parent
- **Persistent pair counts**: pair→words index updated only for affected words after each merge (instead of re-scanning all words)
- **Lazy-deletion heap**: fetches max `(count, pair)` with tie-break favoring lexicographically greater byte pair
- Output is **identical** to the naive trainer (verified on tiny corpus and TinyStories prefix)

## Phase 3 — Training Infrastructure

Hand-written training loop with:

- **Cross-entropy**: numerically stable log-softmax + NLL (`train/cross_entropy.py`)
- **AdamW**: decoupled weight decay with bias correction (`train/adamw.py`)
- **Cosine schedule with linear warmup** (`train/schedule.py`)
- **Gradient clipping** by global norm (`train/training_loop.py`)
- **Memmap data loader**: random batches from `uint16` memmap, targets = inputs shifted by 1 (`train/loader.py`)
- **Checkpoint save/resume**: model, optimizer, scheduler state, step, best loss (`train/checkpoint.py`)

Train:
```bash
python train/training_loop.py \
  --memmap data/tokenizer/tinystories_uint16.bin \
  --vocab-size 10000 --d-model 512 --n-layers 4 --n-heads 16 \
  --d-ff 2048 --batch-size 16 --seq-len 256 --max-steps 5000 \
  --device cuda --save-dir checkpoints/
```

**Expected initial loss:** ~9.21 (ln(10000))  
**Expected trained loss:** ~2.5–3.5 after 5,000 steps

## Phase 4 — Generation

Autoregressive generation with temperature and top-p (nucleus) sampling, plus optional KV cache.

```bash
# Vanilla generation
python train/generate.py \
  --checkpoint checkpoints/final.pt \
  --vocab-size 10000 --d-model 512 --n-layers 4 --n-heads 16 --d-ff 2048 \
  --max-new-tokens 50 --temperature 0.8 --top-p 0.9 \
  --prompt "Once upon a time" --device cuda

# With KV cache (slightly faster)
python train/generate.py \
  --checkpoint checkpoints/final.pt \
  --vocab-size 10000 --d-model 512 --n-layers 4 --n-heads 16 --d-ff 2048 \
  --max-new-tokens 50 --temperature 0.8 --top-p 0.9 \
  --prompt "Once upon a time" --device cuda --use-kv-cache
```

## Phase 5 — Systems Benchmarks

Measured on RTX 3050 (4 GB VRAM), batch=8, seq_len=256:

| Configuration | ms/iter | tok/s | Memory | Notes |
|---------------|---------|-------|--------|-------|
| fp32 eager | 135.46 | 15,119 | 100.3 MB | Baseline |
| bf16 autocast | 80.26 | 25,518 | 58.3 MB | **1.69× speedup, 42% less memory** |
| torch.compile | Skipped | — | — | Triton not available on Windows |
| Triton FlashAttention-2 | Skipped | — | — | Triton not available on Windows |

**Optimality finding:** bf16 autocast is the sweet spot for this hardware — near-maximum throughput with minimal memory. torch.compile and FlashAttention-2 require Triton, which is not officially supported on Windows.

Run benchmarks:
```bash
python train/benchmarks.py
```

## Design Decisions & Lessons

1. **Everything from scratch**: No `nn.MultiheadAttention`, no `nn.CrossEntropyLoss`, no HF tokenizers. Every component is hand-written and tested against PyTorch references.
2. **Bytes everywhere**: Tokenizer operates purely on `bytes` objects — no `str`/`int` conversions in the merge loop.
3. **Weight tying**: Input embedding and output projection share weights, reducing params by ~5M.
4. **Pre-norm architecture**: RMSNorm before each sublayer, residual after — more stable than post-norm.
5. **bf16 on RTX 3050**: Provides the best throughput/memory trade-off on Ampere consumer GPUs.
6. **500 steps is not enough**: A 22M parameter model on 51MB needs 50,000+ steps for coherent output. 500 steps produces gibberish — that's expected, not a bug.
